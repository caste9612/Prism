Prism 2.2.2 analyses large network folders much faster: each file is opened and read once, network shares read several files at a time, and pictures get their print from the same reading as their hash. It no longer closes on a video whose frames are smaller than expected, and it reads and counts less while idle. It includes 2.2.1, 2.2.0 and 2.1.5, which were tried on one PC and not published.

## Faster content analysis

On a company file server, the analysis of a shared folder with 2.5 million files took a day: 21
hours and a half for the hashes, one file at a time, and 5 more hours to read the pictures again
for their prints. Most of that time went in waiting for the server for each file, not in
reading it. On another shared folder of the same server, Prism 2.2 hashed 1.4 million files in
3 hours (135 files a second instead of 33), then the large files at the full speed of the
network.

- **Each file is opened once.** Its size and date are read from the open file instead of
  opening it again by name.
- **Small files and pictures are read once.** Files up to 1 MB are read whole at the first
  step, which keeps their full hash too, and pictures get their print from the same bytes as
  their hash: no second and third reading.
- **Network shares read 4 files at a time.** Local disks still read one at a time: a hard disk
  is slower with two files at once, and on an SSD it makes no measurable difference.
- **Less memory while the analysis runs.** Counting the pictures and videos left no longer
  loads every file of the disk in memory.

## Less work while idle

- **Files always in use are no longer read for nothing.** A large file whose date is not the
  one of the catalog was read to its end before Prism noticed. On one PC, three such files
  (38 GB in all) were read every 30 minutes, all day. Prism now asks the size and date of a
  large file before reading it.
- **The progress of the analysis is counted less often.** On a disk that changes all the time
  (a system disk), Prism counted the files left every 30 seconds, reading its catalog for
  seconds each time. It now counts as often as the count is cheap: at once on small disks,
  every couple of minutes on a disk with millions of files.

## Fixes

- **Prism closed while printing the videos of a folder**: the videos are decoded by Windows,
  inside Prism. Prism read the pixels of a frame by the size it expected, and a frame smaller
  than that (a video changing size midway) could be read past its end, which closes the program
  at once, without a word in the log. Each frame is now read only inside what Windows gives, and a
  short frame marks the video as not decodable. And Prism notes in its catalog the video it is
  decoding on each disk: if it ever goes down during a decoding (a codec of Windows may), it
  does not try that video again, and the log names it.
- **TypeScript declarations counted as videos**: `.mts` is the extension of camcorder videos
  and of TypeScript modules. The `.d.mts` files, thousands in a `node_modules` folder, are no
  longer taken for videos.
- **System disk left behind for 30 minutes** (from 2.1.5): Prism reads the files changed on an
  NTFS disk one after the other while programs keep working. When a program renamed a file over
  another between two of those reads, both seemed to have the same name: the update failed, and
  the catalog of the disk waited 30 minutes for a full reading. Prism now notices it and reads
  those files again 15 seconds later.
- **The same entries rewritten at every full reading** (from 2.1.5): when a file has several
  names in one folder (hard links, as the `git-*.exe` programs of Git for Windows), its names
  swapped their catalog entries at every full reading of the disk. The catalog was right, but
  written for nothing. Each name now keeps its entry.

## Diagnostics

- The log says how long each step of the analysis took, how much it read and how many files it
  read at a time, and every 10 minutes how far a long analysis got.
- The log says why pictures and videos could not be decoded: the most frequent reasons, with
  how many files each.
- The log says why Prism read a whole NTFS disk again instead of using its journal, and how
  long the check of the catalog took at a start after Prism was closed abruptly.
- Errors of the program itself (panics) are written to the log.
- The diagnostic package lists, for each disk, its entries and how far the content analysis
  got (files, images, videos), and for each running job its disk, progress and duration.

## Install

Prism 2.0 and 2.1 update themselves: *Settings › Updates › Install and restart*. Otherwise
download `Prism_2.2.2_x64-setup.exe` below and run it (Windows 11, 64-bit). The installer is
not signed yet: if SmartScreen says "Windows protected your PC", choose *More info › Run anyway*.

## In italiano

Prism 2.2.2 analizza molto più in fretta le cartelle di rete grandi: ogni file si apre e si
legge una volta sola, le cartelle di rete leggono più file alla volta e le immagini ricevono
l'impronta dalla stessa lettura dell'hash. Non si chiude più su un video con fotogrammi più
piccoli del previsto, e a riposo legge e conta meno. Comprende la 2.2.1, la 2.2.0 e la 2.1.5,
provate su un PC e non pubblicate.

- **Analisi più veloce**: su un file server aziendale l'analisi di una cartella condivisa con
  2,5 milioni di file richiedeva un giorno, quasi tutto passato ad aspettare il server per ogni
  file. Ora ogni file si apre una volta; i file fino a 1 MB e le immagini si leggono una volta
  sola (hash e impronta dagli stessi byte); le cartelle di rete leggono 4 file alla volta, i
  dischi locali uno. Su un'altra cartella dello stesso server: 1,4 milioni di file in 3 ore (135
  al secondo invece di 33), poi i file grandi alla velocità piena della rete. Contare le
  immagini e i video da fare non carica più in memoria tutti i file del disco.
- **Meno lavoro a riposo**: un file grande con una data diversa da quella del catalogo veniva
  letto fino in fondo prima che Prism se ne accorgesse; su un PC, tre file sempre in uso (38 GB
  in tutto) venivano letti ogni 30 minuti. Ora Prism chiede dimensione e data prima di leggere
  un file grande. E su un disco che cambia di continuo l'avanzamento dell'analisi non si
  riconta più ogni 30 secondi: subito sui dischi piccoli, ogni paio di minuti su un disco con
  milioni di file.
- **Prism si chiudeva durante le impronte dei video di una cartella**: un fotogramma più
  piccolo del previsto (un video che cambia dimensione a metà) poteva leggersi oltre la fine, e
  il programma si chiude di colpo senza scrivere nulla. Ora ogni fotogramma si legge solo dentro
  quello che Windows fornisce; e Prism annota nel catalogo il video che sta decodificando su
  ogni disco: se si chiude durante una decodifica, quel video non viene più riprovato e il log
  lo nomina.
- **Dichiarazioni TypeScript contate come video**: `.mts` è l'estensione dei video delle
  videocamere e dei moduli TypeScript. I file `.d.mts`, migliaia in una cartella
  `node_modules`, non sono più presi per video.
- **Disco di sistema indietro di 30 minuti** (dalla 2.1.5): se un programma rinominava un file
  sopra un altro mentre Prism leggeva i file cambiati, l'aggiornamento falliva e il catalogo del
  disco aspettava 30 minuti una lettura completa. Ora Prism rilegge quei file 15 secondi dopo.
- **Le stesse voci riscritte a ogni lettura completa** (dalla 2.1.5): i nomi di un file con più
  hard link nella stessa cartella si scambiavano le voci del catalogo a ogni lettura. Ora ogni
  nome tiene la sua voce.
- **Diagnostica**: il log dice quanto è durato ogni passo dell'analisi, quanto ha letto e con
  quanti file alla volta, ogni 10 minuti a che punto è un'analisi lunga, perché immagini e video
  non si sono potuti decodificare (i motivi più frequenti), perché Prism ha riletto per intero
  un disco NTFS e quanto è durato il controllo del catalogo dopo una chiusura brusca; gli
  errori del programma stesso finiscono nel log. Il pacchetto diagnostico riporta per ogni
  disco le voci e l'avanzamento dell'analisi, e per ogni lavoro in corso il disco,
  l'avanzamento e la durata.

Le versioni 2.0 e 2.1 si aggiornano da sole: *Impostazioni › Aggiornamenti › Installa e
riavvia*.
