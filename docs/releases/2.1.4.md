Prism 2.1.4 keeps large network folders and NTFS disks up to date with far less work, and lets the content analysis of busy PCs and file servers move forward without restarting all the time. It includes the fixes of 2.1.2 and 2.1.3, which were tried on one PC and not published.

## Fixes

- **Network folders read again in full** — on a busy file server, a change made directly in a
  top-level folder (even just its date, when a file is created in it) made Prism read the whole
  shared folder again: 3.2 million entries, 6 to 9 minutes, back to back all working day. Prism
  now reads only the list of each folder that changed; subfolders it already knows stay as they
  are, and new ones are read in full. A complete re-read happens only when Windows loses
  notifications, spaced as in 2.1.1.
- **NTFS disks not updated** — Prism reads the files changed on an NTFS disk through Windows,
  which gives their records already corrected. A record can still hold, as ordinary data, the
  value Windows uses to check it: Prism took those records for damaged ones and tried the same
  update again every 16 seconds, so the catalog of the disk stayed where it was. Those records
  are now read normally. And when the updates of an NTFS disk fail one after the other for 10
  minutes, whatever the reason, Prism reads the disk again from its file table (seconds) and
  starts again from there.
- **Content analysis that did not move forward**
  - The analysis always leaves one worker free, and gives its own to an update only after the
    update has waited 30 seconds: updates last seconds, and stopping the analysis for each one
    made the analysis of a large network folder restart every few minutes.
  - Updating a few folders of a network share no longer stops the analysis of the other shares
    of the same server.
  - Images too large to be compared (over 512 MB, such as virtual slides) no longer count as
    work left: the analysis of a folder full of them restarted every 2 minutes doing nothing.
  - Files modified in the last 10 minutes wait for a later round, and after a complete round
    the next one starts 10 minutes later instead of 2: on a system disk where hundreds of files
    change all the time, a round no longer starts every 3 minutes.
  - When the only files left are in use, unreadable or changed since the catalog was updated,
    the next round comes after 30 minutes instead of 2.
- **Diagnostics** — once an hour the log sums up the updates of each watched folder (how many,
  how many paths, how long), so a diagnostic package shows their load.

## Install

Prism 2.0 and 2.1 update themselves: *Settings › Updates › Install and restart*. Otherwise
download `Prism_2.1.4_x64-setup.exe` below and run it (Windows 11, 64-bit). The installer is
not signed yet: if SmartScreen says "Windows protected your PC", choose *More info › Run anyway*.

## In italiano

Prism 2.1.4 tiene aggiornate le grandi cartelle di rete e i dischi NTFS con molto meno lavoro, e
fa avanzare l'analisi del contenuto sui PC e sui file server affollati senza farla ripartire di
continuo. Comprende le correzioni della 2.1.2 e della 2.1.3, provate su un PC e non pubblicate.

- **Cartelle di rete rilette per intero**: su un file server affollato, un cambio fatto
  direttamente in una cartella di primo livello (anche solo la sua data, quando ci si crea un
  file) faceva rileggere a Prism tutta la condivisione: 3,2 milioni di voci, da 6 a 9 minuti,
  una dopo l'altra per tutta la giornata di lavoro. Ora Prism rilegge solo l'elenco di ogni
  cartella cambiata; le sottocartelle che conosce già restano come sono, quelle nuove si leggono
  per intero.
- **Dischi NTFS non aggiornati**: un file letto tramite Windows poteva essere preso per
  rovinato, e il journal di tutto il disco restava fermo dietro di lui. Ora quei file si leggono
  normalmente; e se gli aggiornamenti di un disco NTFS falliscono di fila per 10 minuti, per
  qualsiasi motivo, Prism rilegge il disco (pochi secondi) e riparte da lì.
- **Analisi del contenuto che non avanzava**: l'analisi lascia sempre libero un posto e cede il
  suo a un aggiornamento solo se questo aspetta da 30 secondi; aggiornare poche cartelle di una
  condivisione non ferma più l'analisi delle altre condivisioni dello stesso server; le immagini
  troppo grandi per il confronto (oltre 512 MB, come i vetrini virtuali) non contano più come
  lavoro da fare; i file modificati negli ultimi 10 minuti aspettano un giro successivo, e dopo
  un giro completo il successivo parte dopo 10 minuti invece di 2; quando restano solo file in
  uso, illeggibili o cambiati rispetto al catalogo, il giro successivo arriva dopo 30 minuti.
- **Diagnostica**: ogni ora il log riassume gli aggiornamenti di ogni cartella sorvegliata.

Le versioni 2.0 e 2.1 si aggiornano da sole: *Impostazioni › Aggiornamenti › Installa e
riavvia*.
