Prism 2.1.5 keeps the catalog of a busy system disk up to date while programs update themselves, stops rewriting the same entries at every full reading of a disk, and tells more in a diagnostic package.

## Fixes

- **System disk left behind for 30 minutes** — Prism reads the files changed on an NTFS disk one
  after the other while programs keep working. When a program renamed a file over another
  between two of those reads, both seemed to have the same name: the update failed, and the
  catalog of the disk waited 30 minutes for a full reading. Prism now notices it and reads
  those files again 15 seconds later.
- **The same entries rewritten at every full reading** — when a file has several names in one
  folder (hard links, as the `git-*.exe` programs of Git for Windows), its names swapped their
  catalog entries at every full reading of the disk: 1,881 entries on the PC where it was seen.
  The catalog was right, but written for nothing. Each name now keeps its entry.

## Diagnostics

- The log says why Prism read a whole NTFS disk again instead of using its journal.
- The diagnostic package lists, for each disk, its entries and how far the content analysis
  got (files, images, videos), and for each running job its disk, progress and duration.

## Install

Prism 2.0 and 2.1 update themselves: *Settings › Updates › Install and restart*. Otherwise
download `Prism_2.1.5_x64-setup.exe` below and run it (Windows 11, 64-bit). The installer is
not signed yet: if SmartScreen says "Windows protected your PC", choose *More info › Run anyway*.

## In italiano

Prism 2.1.5 tiene aggiornato il catalogo di un disco di sistema anche mentre i programmi si
aggiornano, non riscrive più le stesse voci a ogni lettura completa di un disco, e dice di più
nel pacchetto diagnostico.

- **Disco di sistema indietro di 30 minuti**: Prism legge uno dopo l'altro i file cambiati su un
  disco NTFS, mentre i programmi lavorano. Se un programma rinominava un file sopra un altro fra
  due letture, i due sembravano avere lo stesso nome: l'aggiornamento falliva e il catalogo del
  disco aspettava 30 minuti una lettura completa. Ora Prism se ne accorge e rilegge quei file 15
  secondi dopo.
- **Le stesse voci riscritte a ogni lettura completa**: i nomi di un file con più hard link
  nella stessa cartella (come i programmi `git-*.exe` di Git for Windows) si scambiavano le voci
  del catalogo a ogni lettura completa del disco. Il catalogo era giusto, ma riscritto per
  niente. Ora ogni nome tiene la sua voce.
- **Diagnostica**: il log dice perché Prism ha riletto per intero un disco NTFS; il pacchetto
  diagnostico riporta per ogni disco le voci e l'avanzamento dell'analisi, e per ogni lavoro in
  corso il disco, l'avanzamento e la durata.

Le versioni 2.0 e 2.1 si aggiornano da sole: *Impostazioni › Aggiornamenti › Installa e
riavvia*.
