# Prism — Decisioni e revisione dell'utente

> Registro delle decisioni prese senza l'utente, con le alternative e il modo di cambiarle, di
> ciò che resta a lui e dei limiti noti. Nato per la revisione finale del 2026-11-07, continua
> dopo il rilascio. Chi aggiunge una voce la mette in fondo alla tabella giusta, con data e
> tappa.

## 0. In breve

Prism **2.0.0** è pubblicato (release `v2.0.0` su GitHub, 2026-11-08) e installato sul PC
dell'utente; le versioni successive escono dal workflow *Release* e arrivano alle copie
installate con l'aggiornamento automatico. Tutte le funzioni della SPEC (F01–F22) sono
implementate; ogni criterio ha test automatici (`scripts/check.ps1`, CI su GitHub, test elevati
sul disco virtuale PRISMTEST) o una voce delle checklist di §4 (NF8). Le decisioni prese senza
l'utente sono in §1 (D1–D66), i limiti noti in §3. Restano le cose che solo l'utente può fare
(§2):

1. **Provare Prism su un altro PC** con altri dischi e altre cartelle di rete (U3, checklist
   T10): installazione, riavvio, aggiornamento automatico.
2. **Una copia della chiave degli aggiornamenti fuori dal PC** (U7).
3. **Rimuovere il runner amministratore** da questa macchina quando lo sviluppo finisce (U6).
4. **Firma del codice**, se e quando la si vorrà (U1).

## 4. Come provare l'app

Le prove che cancellano, spostano o puliscono file si fanno **solo** sul disco di test
PRISMTEST o in cartelle di prova (TESTING S5).

### Avvio

Prima si chiude il Prism installato (tray › *Esci*): ha lo stesso identificativo, quindi
l'istanza unica farebbe uscire subito l'app di sviluppo, e usa la stessa scorciatoia `Ctrl+Space`.
Poi, da un terminale nella cartella `D:\Progetti\Github\Prism-next`:

```powershell
npm --prefix ui ci                  # una volta: dipendenze dell'interfaccia
npm --prefix ui run build           # interfaccia → ui/dist
cargo run -p prism-app --features custom-protocol
```

- La build di debug **non** chiede l'amministratore (manifest `asInvoker`): avviata da un
  terminale normale indicizza leggendo le cartelle e non segue il journal; avviata da un
  terminale **elevato** usa la MFT e si aggiorna da sola (come il prodotto finale). Catalogo di
  prova in `%LOCALAPPDATA%\PrismDev\app\catalog.db`: si può cancellare per ripartire da zero.
- La build di release usa la cartella dati del Prism installato
  (`%LOCALAPPDATA%\com.prism.catalog`): **non si avvia su questo PC**, dove c'è il catalogo vero
  dell'utente (TESTING S4). Il prodotto finale si prova installando una release, su un altro PC o
  in Windows Sandbox (`scripts/sandbox-test.ps1`).
- Solo l'interfaccia, con dati d'esempio, nel browser: `npm --prefix ui run dev` e aprire
  `http://localhost:5173`.
- Da T6 l'app legge in sottofondo, a priorità minima, il contenuto dei file dei dischi
  collegati e indicizzati, cartelle di rete comprese (D58) (solo lettura: serve a riconoscere i duplicati). Si sospende dal
  menu del tray o da *Impostazioni*, dove si possono anche escludere singoli dischi.
